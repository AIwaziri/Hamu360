# Hamu360

Enterprise SharePoint Framework (SPFx) + React + TypeScript frontend for Hamu360. SharePoint is the backend only — this repository owns the client-side application.

**Sprint 0 status:** project foundation only. No feature UI (no dashboard, no hero, no pages) has been built yet — see [ARCHITECTURE.md](./ARCHITECTURE.md) for the full rationale behind every configuration choice in this repo.

## Prerequisites

- Node.js `>=22.14.0 <23.0.0` (pinned in `package.json#engines` to match the SPFx 1.23 toolchain requirement)
- npm (this project uses `package-lock.json`; don't mix in yarn/pnpm lockfiles)
- Access to a Microsoft 365 / SharePoint Online tenant for `gulp serve` against a real site (the local workbench also works without one)

## Getting started

```bash
npm install
npm run serve      # gulp serve — opens the SharePoint workbench in config/serve.json
```

## Scripts

| Script                     | What it does                                              |
| -------------------------- | --------------------------------------------------------- |
| `npm run serve`            | Local dev server + SharePoint workbench (`gulp serve`)    |
| `npm run build`            | Compile + bundle for debug (`gulp bundle`)                |
| `npm run package-solution` | Produce the `.sppkg` package under `sharepoint/solution/` |
| `npm run clean`            | Remove build output (`gulp clean`)                        |
| `npm run test`             | Run the SPFx test task (`gulp test`)                      |
| `npm run type-check`       | Strict TypeScript check only, no emit — see caveat below  |
| `npm run lint`             | ESLint over `src/**/*.{ts,tsx}`                           |
| `npm run lint:fix`         | ESLint with autofix                                       |
| `npm run format`           | Prettier — write mode                                     |
| `npm run format:check`     | Prettier — check mode (CI-friendly, no writes)            |

**Caveat on `type-check`:** SCSS Modules get their TypeScript typings (`*.module.scss.ts`) generated by the gulp `sass` subtask, not by `tsc` itself. Run `npm run build` (or `gulp serve`) at least once after a fresh clone before `npm run type-check` will pass cleanly — after that, `tsc` alone is fine for fast iteration since the generated stubs stay on disk (they're gitignored, not committed).

## Production build

```bash
npm run build -- --ship
npm run package-solution -- --ship
```

Produces `sharepoint/solution/hamu-360.sppkg`, ready to upload to the tenant App Catalog.
